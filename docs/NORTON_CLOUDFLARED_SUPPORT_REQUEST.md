目前僅請您提供診斷結論、適用版本、最小作用範圍、風險、回復方法與是否需重啟的書面說明。
**尚未授權遠端套用、調整防火牆／憑證／Norton 設定、安裝信任根、升級或重啟任何服務。**

## 3. 目的地、SNI 與原始憑證／錯誤

兩個區域的 DNS endpoint 為 `region1.v2.argotunnel.com`、`region2.v2.argotunnel.com`。
**DNS endpoint 與 TLS SNI 不同**；本案希望精確區分：

| 用途 | 採證 IP／port | TLS SNI | 2026-08-30 台北時間 | 實際結果 |
| --- | --- | --- | --- | --- |
| precheck 對應探測 | `198.41.192.227:7844` TCP | `probe.cftunnel.com` | 15:22:50.979524–15:22:51.656418 | TCP 接通；TLS code 20；OpenSSL exit 1；未送 ALPN |
| 正式 HTTP2 SNI 對照 | `198.41.200.233:7844` TCP | `h2.cftunnel.com` | 15:23:38.841287–15:23:38.905612 | TCP 接通；TLS code 20；OpenSSL exit 1；offer ALPN h2 |

IP 是當時固定抽測目標，不是永久 allowlist，也不代表整個 Cloudflare 網路均已測試。
這是到 Cloudflare edge 的連線；不是把 LINE 公開 webhook URL 或本地 origin 加入例外。

兩筆都得到同一張公開 **leaf certificate**。原始解析結果：

```text
subject=O=CloudFlare, Inc., OU=CloudFlare Origin CA, CN=CloudFlare Origin Certificate
issuer=OU=generated by Norton Antivirus for untrusted server certificates, O=Norton Web/Mail Shield, CN=Norton Web/Mail Shield Untrusted Root
notBefore=Dec 13 14:58:00 2023 GMT
notAfter=Dec  9 14:58:00 2038 GMT
sha256 Fingerprint=AA:AB:07:15:BB:93:2D:A3:16:9A:E1:75:CA:00:D4:35:B7:2E:C9:6F:8A:81:B1:1F:B0:DA:D7:E0:19:37:3B:73
X509v3 Subject Alternative Name:
    DNS:*.cftunnel.com, DNS:cftunnel.com
```

上面指紋屬於收到的 leaf，**不是 Norton root 的指紋**；未取得完整 Norton 根憑證／鏈身分。
SAN 涵蓋兩個 SNI，日期未過期；觀察到的錯誤是信任鏈而非到期。

```text
Verification error: unable to get local issuer certificate
Verify return code: 20 (unable to get local issuer certificate)
verify error:num=20:unable to get local issuer certificate
```

驗證全程開啟（含 hostname 與 verify_return_error）。診斷只對單次程序使用同版本
cloudflared 官方公開 CA bundle，未匯入 Windows、Norton 或正式 cloudflared 信任庫。
其組合不完全等於 Go 的 Windows system pool 加官方 CA，因此不冒稱兩者執行環境相同。
TLS 因驗證失敗中止，沒有成功的 HTTP2 註冊或 h2 協商證據；
`No ALPN negotiated` 不能單獨推論對端不支援 HTTP2。

歷史 14:24:15 的兩個 precheck FAIL 只記 `blocked or unreachable`，沒有底層 TLS error。
目前的 Norton 替換／驗證失敗是直接證據；把它追溯成每一筆歷史 FAIL 的原因，仍需 Norton
事件／規則命中來確認，不能只憑泛用「Allow outbound TCP」文字認定 Windows 防火牆根因。

## 4. 請 Norton 逐項回覆

1. **命中哪個模組與政策？** 這個 issuer／OU 是否表示 Norton 判定原伺服器鏈不受信任，
   並產生用來阻止連線的替換憑證？請區分 Safe Web／Web Shield／Mail Shield／Smart Firewall／
   VPN 或其他模組，提供事件／規則 ID、觸發條件與判定依據；不能只回覆「埠被擋」。
2. **是否相容於 cloudflared 的 CA／TLS 信任模型？** 對使用內建官方 CA 的 Go 客戶端及
   Cloudflare Origin CA 類型的 edge 憑證，是否有已知誤判或 TLS inspection 相容性問題？
   若有修正版，請提供確切產品 build、修正公告、作用範圍與是否需要重啟；本案暫不執行升級。
3. **是否支援真正的 per-application TLS inspection bypass？** 能否限縮到上面的
   cloudflared.exe，而非把整個資料夾或所有防毒掃描排除？比對是完整路徑、簽署者、hash、
   使用者還是組合？更新 binary／移動路徑後如何失效或重新審核？能否保留檔案掃描與防火牆？
4. **是否支援精確 SNI 的 TLS inspection bypass？** 可否只限 `probe.cftunnel.com` 與
   `h2.cftunnel.com`，且作用於非瀏覽器 TCP/7844？能否再和指定執行檔交集限定？
   請說明是 DNS hostname、SNI、URL 或 IP 的比對，不建議用整個 `*.cloudflare.com`、
   `*.trycloudflare.com`、所有 `*.cftunnel.com` 或寬廣網段代替尚未確認的最小例外。
5. **一般排除與 TLS 例外是否不同？** 請明確確認 Antivirus exclusion、Safe Web website exclusion、
   Smart Firewall application allow 對本案各自會改變什麼，哪一個能真正停止憑證替換。
   若本產品只支援全域關閉 HTTPS 檢查，請直接說明「不支援所需的限縮例外」。
6. **規則是否影響現有 QUIC？** Windows 版本的 HTTPS 與 QUIC/HTTP3 檢查是否由不同模組處理？
   例外是否同時改變 UDP/7844、其他程式或其他協定？請列出優先序與可能交互作用；
   目前 QUIC 可用，不代表已證明 Norton 完全不檢查 QUIC。
7. **套用與回復會不會中斷服務？** 請逐項說明是否即時生效、是否需要 Norton 服務／電腦／
   cloudflared 重啟，或重置既有 socket／網路介面。請提供生效與回復的原理及預期影響，
   **我們不能先假設 TLS 例外必定零中斷**。先提供方案，不直接操作。
8. **如何留下可稽核的最小範圍？** 請提供正式文件、支援的 exact build、規則匯出／恢復方法、
   有效期限、更新後持續性，以及如何確認只套用到指定 executable／SNI；不要降低整機信任驗證。
9. **如何補齊歷史原因證據？** 請告知可唯讀取得 2026-08-30 14:24:00–14:24:30、

   規則命中欄位。如需另外啟用詳細記錄、收集記憶體或完整流量，請先列資料範圍與影響，
   不要求上傳整機紀錄、LINE token、私鑰、DB 或用戶訊息。
10. **如何驗證修復而不是只看到 PASS？** 請確認授權後可用同一組 IP/SNI 的少量、驗證開啟

    正式 cloudflared 的 precheck／HTTP2 註冊與 LINE 路徑。請勿把 TLS 成功直接當作備援可切換。
