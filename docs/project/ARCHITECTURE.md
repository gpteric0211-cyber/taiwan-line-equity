# 架構與維護

## 分層

`equity` 管理應用生命週期，既有 `review_src` 保留正式分析來源，避免重寫導致指標或裁決規則漂移。

```text
手機網頁 / LINE webhook
        ↓
api → services → repository / adapter / analysis → core
        ↓
行情庫 / 帳號庫 / 加密持股庫 / 原 LINE 記憶庫
```

網頁 `/api/portfolio` 與 LINE 持股指令共用 `PortfolioStore`、持股驗證器和圖片辨識服務。一般股票問題仍經原有 `answer_stock_question`、資料包、模型 admission 與裁決服務。新持股狀態只提供「已有部位」背景，不改寫行情、評分或主要結論。

既有大型 `app.py` 與 `line_bot_service.py` 保留相容邊界。新功能不再往內堆疊 SQL 或圖片辨識邏輯；後續拆分應依測試涵蓋的功能逐步抽出，避免一次移動全部分析程式。

## 資料庫責任

- **行情庫**：歷史價格、籌碼、品質標記、新聞、公司行動及既有審計資料。
- **帳號庫**：一次性從舊行情庫遷移帳號相關五表；後續登入、session、自選股走獨立庫。原五表保留作遷移來源，不再作為帳號寫入入口。
- **持股庫**：已確認持股、到期草稿、一次性綁定、同意版本與關聯。內容加密，owner 使用不可逆識別衍生值；網頁與 LINE 只有明確綁定才共用紀錄。
- **LINE 記憶庫**：沿用原加密與保存設定，不因新增持股而提高保存期限。

每個 repository 應明確關閉連線，寫入使用交易，讀取使用唯讀連線。檔案 URI 由 Path.as_uri 建立，支援空白、中文及特殊字元。遷移使用 SQLite backup API，驗證完成並關閉所有 handle 後才發布檔案。

## 安全與資料來源

HTTP 統一入口要求登入才能存取業務 API；內部 Bot API 使用獨立 token；LINE 驗證原始 request body 的簽章。首次帳號建立及敏感系統設定限主機 loopback。持股修改另要求同源與自訂 request header。

圖片先限制大小、驗證及重編碼，只擷取代號、數量、單位及每股成本；圖片內文字視為輸入資料，不可作為指令。模型輸出是草稿，無明確股／張單位或數值不合法時不得保存。使用者可刪除與匯出確認紀錄。

新聞永久保存的是事件摘要／metadata 與來源，不代表內容已核實。原文以來源連結呈現，不以永久保存機制大量存放新聞全文。

## 排程與程序

- 台北交易日：capture 與 finalize 使用原隔離更新流程及原共用寫入鎖。
- 外部新聞／事件：沿用五個既有時段，呼叫原外部分析更新器及同一把寫入鎖。
- 每階段完成即保存 checkpoint；失敗稍後重試，完成階段不因程序重新啟動而重複。
- 新啟動器只停止自己建立的程序樹。Windows 與 POSIX 的差異集中在 `equity/processes.py` 和鎖的實作。
- 到期持股草稿、綁定碼與圖片等待狀態由排程清理，並於存取時拒絕過期 token。

## 升級

先備份、保留金鑰，再於獨立環境更新依賴並跑離線測試。驗證資料庫遷移、GET 路徑、LINE payload 和本機模型後才切換執行程序。不要將模型、資料庫或歷史輸出加入 Python 套件。更新 uv.lock 必須和依賴變更一起審查。
